# Skew motion actual browser receiving

Run the maintained product server and strict isolated browser wrapper:

```sh
BROWSER_EXECUTABLE_PATH=/path/to/qualified-chrome \
BROWSER_ARTIFACT_DIR=/path/to/new-receipt \
node scripts/coupling-skew-motion-browser.mjs
```

The wrapper reuses `scripts/support/chromium-sandbox.mjs`; it does not download a browser, weaken its sandbox, or use a shared profile. It serves the maintained coupling page and collects real downloads. `receiveSkewMotion` also accepts the same existing CDP receiver callbacks as the velocity-comparison receiver, so an already qualified owned browser can run the same journey.

Ten groups cover: fitting without adoption; explicit source-paired copying into controls and renewed declaration; actual paths changed by the sign of G; transformed modes and sampled power; original-source v4 download and fresh-page rederivation; malformed and legacy-version refusal; revocation of pairing by fit settings and response-source changes; conditional copying with failed held-source receiving still visible; old parameter and selected-release copies clearing G; trusted keyboard submission and actual playback; and desktop/narrow layout.

The response notebook is downloaded before copying and compared with the evidence in the resulting motion download. Original velocity diagnostics remain unchanged by copying. The receiver does not fit sources in a separate UI or adopt a model automatically. PNGs show motion controls/plot, power and mode inspection at1440px and390px. The JSON receipt retains check names, exceptions, external requests, sandbox admission and runtime identity. These tests qualify this bounded conditional application path, not physical validation or a general error bound.
